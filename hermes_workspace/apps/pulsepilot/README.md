# PulsePilot v3 — диспетчер параллельных проектов

Теперь 3, 4 или 7 независимых проектов могут выполняться одновременно. Приложение управляет поручениями и очередью решений владельца. Работающие агенты продолжаются при переключении карточек и при рабочем блоке владельца.

## Что видно на экране

- Слева вертикальный список направлений; горизонтального скролла проектов больше нет.
- В центре карточки: цель, подтверждённый факт, условие масштаба, конкретный TODO и статус запуска. Цель и факт можно редактировать.
- Справа «Нужно моё решение»: вопрос агента, ошибка, результат на проверке, неподтверждённый статус или давно отсутствующий прогресс.
- «Ушёл на работу · 30 мин» откладывает полноэкранные уведомления. Агенты не останавливаются. Очередь остаётся видна; при возвращении можно разбирать её.
- Звук и перекрытие экрана относятся к событиям очереди. Нет циклического требования закончить один проект перед переходом к другому.
- TODO и Wiki разделены. Wiki, риски, цели и явно отложенные работы не выдаются агенту как обычные задачи. Старое правило BI-GATE «один фокус = одна задача в работе» заменено текущим требованием владельца: несколько исполнительских потоков и очередь человеческих решений.

В поставку включён ваш снимок: **10 направлений, 241 узел, 154 незакрытых TODO**. На карточках задан стартовый следующий TODO для каждого направления. Денежные показатели подписаны как снимок 30.09; подключение живого BI в этой версии не выполнено.

## Быстрый рабочий поток

1. В карточке проекта нажми «Подготовить TODO агенту» или выбери другой TODO в дереве.
2. Проверь поручение, локер и ключ общего ресурса. Поручение включает денежную цель и ограничения Wiki. Сохранение ещё не запускает агента.
3. «Передать агенту» создаёт реальный процесс через настроенный Bridge. Без Bridge копирует поручение для ручного локера; после фактического старта выбери «Ещё → Запущен вручную».
4. Повтори для других проектов до лимита 3/4/7. Один проект и один общий ресурс не получают конкурирующих запусков. Результат на проверке сохраняет ресурс до приёмки.
5. У `waiting_input` ответь через карточку. У готового результата запиши, как проверено, и нажми «Принять результат».
6. Принятие отчёта освобождает направление. Большой TODO в серверном дереве закрывается отдельно, когда выполнен целиком. Автопереход по всему roadmap здесь не включён.

Отметки ручного локера подписаны как отметки оператора. `running` от Bridge означает подтверждённый старт процесса, а не гарантию продуктивной работы. Если API отвечает, но worker давно не сообщил прогресс, карточка всё равно попадает в очередь проверки. Нет автоматической повторной отправки после неизвестного исхода.

## Сборка Windows

Нужен .NET 8 SDK. В папке PulsePilot:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт запускает 15 проверок .NET-логики и собирает `dist/PulsePilot.exe`. Снимок дерева и стартовые карточки копируются рядом с EXE. Опрос дерева и агентов идёт параллельно; версия дерева предотвращает постоянный сброс раскрытых узлов. Старые шаги переводятся в карточки «статус не подтверждён», чтобы не потерять текущую работу.

## Настроить настоящий запуск агентов

В `bridge/agent_bridge.py` — самостоятельный HTTP-адаптер на Python 3.10+, без внешних пакетов. Он запускает **ваш настроенный worker**, сохраняет запуски, ограничивает параллелизм, блокирует общий ресурс, передаёт ответы и останавливает процесс. Модель и команды вашего Hermes/SSH-окружения нужно подключить в worker; адрес существующей панели Hermes не является автоматически адресом этого Bridge.

1. Скопируй `bridge/worker.example.json` в `worker.json` и укажи настоящую команду-wrapper вашего агента. Пример — схема параметров, файл `C:/your-agent/run_task.py` не поставляется.
2. Команда получает `{prompt_file}`, `{job_dir}`, `{run_id}`. Это подстановки в массив argv; shell не используется. Путь исполняемого файла и wrapper лучше задавать абсолютный.
3. Запусти Bridge, например в PowerShell:

```powershell
$env:PULSEPILOT_BRIDGE_TOKEN = 'YOUR_RANDOM_TOKEN_AT_LEAST_16_CHARACTERS'
python .\bridge\agent_bridge.py --worker-config .\worker.json --state-dir .\agent-runs --max-parallel 7
```

4. В PulsePilot открой «Agent Bridge…»: URL `http://127.0.0.1:8808`, тот же token, интервал напоминания.

Команда отмены в Bridge прекращает дерево локальных worker-процессов. Если wrapper запускает удалённого агента, передачу отмены этому агенту нужно реализовать в wrapper.

Bridge может жить отдельно от Windows UI. По умолчанию слушает только localhost. Для существующего многосерверного кластера wrapper распределяет задачи по вашим серверам; автоматическое обнаружение 24 Hermes-агентов в этой поставке не реализовано.

### Контракт worker

- Читает UTF-8 `prompt.txt`; пишет прогресс в stdout.
- Для ожидания атомарно заменяет `<job_dir>/status.json`:

```json
{"status":"waiting_input","summary":"Нужны исходные данные","question":"Какой файл использовать?"}
```

- Ответ получает одной JSON-строкой из stdin и дополнительно в `input.json`. Wrapper должен уметь продолжить агентскую сессию по этому ответу.
- Пишет результат в UTF-8 `result.txt`; код выхода 0 означает готовый результат, ненулевой код — ошибку. Итог всё равно проходит приёмку оператора.
- Рекомендуемый статус без вопроса: `running` или `blocked`. Heartbeat без содержательного прогресса не должен скрывать зависание.

### HTTP-контракт

Все запросы с `Authorization: Bearer <token>`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/runs` | `client_job_id`, `project_id`, `node_id`, `resource`, `prompt`; идемпотентный запуск |
| GET | `/runs/{id}` | `id`, `status`, числовая `version`, `summary`, `question`, `result`, `progress_at` |
| POST | `/runs/{id}/input` | `answer`, `expected_version`, `input_id`; повторный ответ не доставляется дважды |
| POST | `/runs/{id}/cancel` | Запрос остановки; конечный статус после завершения процесса |
| POST | `/runs/{id}/resolve` | Разрешение неизвестного исхода после подтверждённой оператором остановки: `status: cancelled`, `evidence`, `expected_version` |

После рестарта Bridge старые незавершённые процессы помечаются `unknown`, удерживают ресурс и не перезапускаются. Проверь их в агентском окружении; для подтверждения остановки запиши факт в карточку и используй соответствующее действие «Ещё». Bridge не принимает подтверждение, если принадлежащий ему процесс ещё работает. На один каталог состояния запускается только один Bridge.

## Проверено и ограничения

- Выполнены **13 Python-проверок** реального запуска worker: 7 параллельных процессов, лимит восьмого, общий ресурс, ввод с версией, повторная доставка, ошибка, остановка, восстановление без дубля, ручное разрешение неизвестного исхода.
- Выполнены проверки XML/XAML, обработчиков, конфигурации и архива.
- Windows/WPF и .NET SDK в среде подготовки отсутствуют. Сборка C#, 15 .NET-проверок и визуальный запуск Windows **не выполнялись**.
- Ваши живые агенты здесь не запускались. Перед использованием подключи wrapper и проверь одно реальное поручение, ответ на waiting_input и остановку. После этого можно увеличивать до 3/4/7.
- Масштабирование бюджетов, закупка доменов, покупки рекламы и автоматический проход всей дорожной карты не выполняются самим диспетчером. Ограничения из дерева передаются исполнителю; обязательные лимиты расходов следует реализовать в вашем worker.
