# HermesWorkspace 1.2 — оркестрация через два чата

## Что это

**Оркестрация → управление задачами внешних клиентов на разных серверах → единый центр инфраструктуры.**

Это рабочий центр управления агентами, которые живут не здесь. Несколько разных
машин — серверов, VPS, рабочих станций — подключаются к приложению как внешние
шлюзы, и дальше ими управляют из одного окна, как если бы все они были рядом.

Цепочка ролей такая:

1. **Оркестрация.** Проект-оркестратор решает, какая задача следующая: читает дерево
   TODO, выбирает узел, даёт исполнителю короткую инструкцию и оценивает результат.
   Он же останавливается и спрашивает владельца, когда без ответа нельзя идти дальше.
2. **Внешние клиенты.** Каждый внешний шлюз — это отдельный сервер со своим адресом,
   своим токеном и своим агентом-исполнителем. Приложение не ставит им общий код и не
   требует доступа к их диску: связь идёт по протоколу TUI-шлюза, а задача уходит
   короткой репликой в чат исполнителя на конкретном сервере.
3. **Единый центр.** Проекты, шлюзы, задачи, прогресс, расход токенов и очередь решений
   живут в одном состоянии. Фоновые ответы продолжаются, пока ты смотришь другой чат;
   переключение диалога не прерывает стриминг соседнего. Разрешения и вопросы модели
   приходят в панель над полем ввода — из любого диалога и в любой момент.

Проще говоря: агенты распределены по разным серверам, а управление ими — в одном
центре, где видно дерево задач, кто что делает и что ждёт тебя.

Каждый внешний клиент остаётся самостоятельным: своя сессия, своя история, свой
контекст. Приложение не смешивает их между собой и не теряет разговор при перезапуске
шлюза — сессия восстанавливается по долговечному id.


## Запуск

Откройте `Windows/HermesWorkspace.exe`. .NET встроен, Windows 10/11 x64. Подробная настройка AI Spy: **START-HERE.md**.

В настройках проекта назначьте шлюз и два существующих диалога: чат оркестратора проекта и чат исполнителя на шлюзе. START запускает планирование TODO → обычная отправка в чат исполнителя → финальный ответ → проверка в выбранном чате оркестратора → закрытие TODO → следующая задача. Оба диалога продолжают свои сессии и историю. Новые API-мосты и отдельные скрипты для связи агентов не участвуют.

Цели, деньги, правки TODO, блокеры и смена подхода обсуждаются с оркестратором в этом же чате. При вопросе владельцу цикл стоит; после ответа и разрешения продолжать (`resume:true`) приложение повторно оценивает уже полученный результат. Непринятые результаты дорабатываются с ограничением числа попыток.

Для ручного режима остаются «Предложить следующий TODO» и «Одобрить запуск». В автономном режиме START является разрешением на последовательные итерации; новая приёмка не оставляет цикл заблокированным на собственном аппруве.

**Важно:** сохранённый старый скилл с `gateway_chat.py` обновите из `tools/skill-short.md`. Прежний скрипт сохранён в `tools/legacy`, а его старый запуск сообщает о новом маршруте.

## Интерфейс

- Слева: проекты-оркестраторы, шлюзы серверов, свободные профили. Проекты без прокрутки, по десять карточек на страницу. Второстепенные разделы имеют отдельную прокрутку.
- В проекте: Чат-оркестратор, Дерево, Задачи, Прогресс, Настройки.
- Workspace: все проекты, запуски, таймеры напоминаний, результаты и очередь решений.
- Дерево показывает задачи, завершённые узлы и контекст по разделам; очередь содержит незавершённые TODO.
- До десяти проектов одновременно; один активный запуск на проект и один на шлюз.

## Данные и восстановление

Состояние хранится в `%APPDATA%\HermesWorkspace\state.json`. При первом запуске HermesChat переносится копированием; исходный файл не изменяется. Если существует `%APPDATA%\PulsePilot\state.json`, импортируются дерево, цели и история поручений. Старые активные поручения требуют проверки перед повторным запуском. Старые токены PulsePilot автоматически не переносятся.

Снимок дерева рядом с exe служит стартовым набором. **Обновить дерево из JSON** импортирует актуальный снимок в данные приложения, сохраняя предыдущий как `.backup`. Принятые итерации учитываются в журнале Workspace. Удалённое дерево/CRM автоматически не меняется. API планировщика PulsePilot и его старые таймеры автоматически не возобновляются.

Напоминание появляется каждые пять минут незавершённой итерации. Это локальный таймер внимания, а не подтверждение живости сервера. Таймеры и исполнение требуют открытого приложения. При закрытии текущие подключения прерываются; при следующем запуске незавершённая работа помечается для проверки. Закрытие соединения не гарантирует остановку всех запущенных на сервере процессов.

Некорректная оценка модели, неизвестный TODO или недостаточные доказательства оставляют результат на ручную приёмку. Неизвестные и отложенные задачи не запускаются автоматически.

## Сборка и проверка

Для пересборки на Windows с .NET 8 SDK: `powershell -ExecutionPolicy Bypass -File .\build.ps1`.

В поставке: готовый exe, исходники объединённого приложения, исходный PulsePilot с bridge и тестами, тесты HermesChat, новые тесты оркестрации.

В окружении подготовки выполнены сборка WPF и публикация win-x64, 63 проверки оркестрации/маршрутизации/пакетов, 6 проверок реального файла дерева и 4 проверки установщика. Интерактивный прогон Windows-интерфейса и реальные подключения к вашим серверам здесь не выполнялись. Подробности — `VALIDATION.md`.


## Мастерская агента

Профили → выберите профиль → **Мастерская агента**.

- **Скиллы** — отдельный экран с плитками: краткое назначение, подключение, редактор Markdown, история версий и вспомогательные файлы. **Скиллы Hermes** импортирует библиотеку с этой машины; с удалённого сервера скиллы нужно перенести файлом или пакетом.
- **Инструменты** — отдельный экран с собственными Python/Shell/PowerShell-скриптами и каталогом реальных тулсетов шлюза. Указание предпочтительного тулсета не ограничивает остальные права агента. Новые скрипты не становятся зарегистрированными нативными инструментами Hermes: они исполняются через terminal после установки файлов.
- **Обучение** — новая задача + критерии → отдельный чат. Отправьте подготовленный запрос. Уточняйте задачу в чате, затем вернитесь в мастерскую: **Сохранить последний ответ**, ручная отметка результата, **Ответ → скилл**. Если тест открывался из плитки скилла, ответ можно проверить в редакторе и сохранить как его следующую версию. Изменение скилла делает старую проверку неактуальной. Отметка «пройдена» — решение пользователя, не автоматический тест модели.
- **Пакет и env** — локальный .env для профиля, экспорт ZIP и импорт независимого профиля. Значения не передаются модели. По умолчанию экспорт содержит только .env.example. Для секретов есть отдельные опции экспорта и импорта. Включённый в архив .env является обычным текстовым файлом.

Подключённые инструкции и текстовые файлы включаются в следующий запрос профиля. Это изменение поведения через инструкции и окружение, а не обучение весов модели. Версии ресурсов в тестовом результате фиксируются по фактическому запросу. Веса моделей, базы данных, сторонние зависимости и серверная память в архив не включаются.

### Развернуть пакет агента на другой машине

Распакуйте экспортированный ZIP. Установщик `install_agent.py` не запускает код пакета и не устанавливает зависимости.

```bash
python3 install_agent.py --target /srv/hermes-agents/my-agent
```

Он копирует SOUL.md, skills и .env.example, сохраняя резервные копии заменяемых файлов. Для импорта реального .env из пакета добавьте `--include-env`: существующие переменные на целевой машине сохраняются, добавляются только отсутствующие.

```bash
HERMES_HOME=/srv/hermes-agents/my-agent hermes chat
```

Модель, провайдер, доступные тулсеты, установленные зависимости и запуск шлюза настраиваются на этой машине отдельно. Приложение не загружает локальный .env в удалённый шлюз автоматически. Импорт в HermesWorkspace сохраняет новый профиль и его ресурсы; отдельная опция переносит .env, если он был экспортирован.

Официальные форматы: [Hermes profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles), [Creating skills](https://hermes-agent.nousresearch.com/docs/developer-guide/creating-skills).
