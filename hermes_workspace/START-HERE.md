# HermesWorkspace 1.2 — настройка AI Spy за один проход

1. Распакуйте архив в папку программы с заменой файлов. Не удаляйте `%APPDATA%\HermesWorkspace`: там ваши чаты, профили, шлюзы и дерево.
2. Запустите `Windows/HermesWorkspace.exe`. Если в прежней папке EXE лежал в другом месте, запускайте именно файл из этого архива.
3. Откройте проект **Spy AI** → **Настройки**. Выберите ваш работающий шлюз AI Spy.
4. В **Чат оркестратора** выберите существующий разговор проекта. В **Чат исполнителя** выберите существующий разговор этого шлюза. Они должны быть разными. Если диалогов нет, создайте их обычными кнопками приложения и вернитесь в настройки.
5. Нажмите **Открыть чат оркестратора**. Напишите цель, критерий результата и бюджет. Если в профиле установлен старый скилл с `gateway_chat.py`, замените его содержимым `tools/skill-short.md` через мастерскую агента.
6. Нажмите **START цикла** в настройках проекта или Workspace. Оркестратор выбирает/декомпозирует TODO, приложение отправляет поручение в выбранный чат исполнителя. Его финальный ответ запускает проверку в том же разговоре оркестратора. Принятый TODO закрывается; цикл планирует следующий.
7. Вопросы по целям, TODO, блокерам и смене подхода обсуждайте в чате оркестратора. Если он запросил владельца, ответьте и напишите «Блокер снят, продолжай». Модель должна вернуть `resume:true`; если не вернула, напишите это требование явно. Полный JSON доступен под ответом. Не нужно создавать API-мост.

## Что видно

В обоих чатах сохраняются настоящие сообщения и выбранные сессии. В чате оркестратора JSON показан как понятный итог с раскрываемыми правками. В Workspace есть кнопки обоих чатов, прогресс, вопросы владельцу и учтённые расходы модели. Отсутствующая цена отмечается явно; выручка не вычисляется из числа задач.

## Параллельная работа

Для каждого проекта выбирайте отдельный чат оркестратора и отдельный диалог исполнителя. На одном шлюзе разные проекты исполняются последовательно; на разных — параллельно, до десяти активных итераций. Общий ресурс отмечайте в теле TODO как `@lock:production-db`. Блокеры: `@blocked`, `@owner`, `@deferred`.

## Границы

START допускает до 50 итераций за сессию; это не денежный лимит. После трёх непринятых результатов одного TODO требуется решение владельца. Разрешения инструментов и уточнения исполнителя отвечаются в его живом чате. Приложение должно оставаться открытым. STOP прекращает локальную отправку/цикл; процессы, уже запущенные на сервере, проверяйте отдельно. После перезапуска незавершённые итерации требуют проверки.

Готовый EXE собран с .NET внутри. Исходники и проверки в архиве. На вашей Windows и реальных шлюзах этой сборке ещё нужен первый живой прогон: одна короткая проверяемая задача AI Spy → ответ → приёмка → следующий TODO.
