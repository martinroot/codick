# Профиль как единый объект: одна страница вместо пяти

Дата: 3 октября 2026. План интерфейса управления профилем: состав, кастомные
скилы, импорт из архива, кнопка «Анализировать», чат с выбранной моделью.

Все утверждения о текущем состоянии проверены по коду, а не по документации.
Ниже указаны файлы, на которых стоит проверка.

## Что уже есть (и на чём строится)

**Экспорт/импорт профиля — есть.** `hermes_cli/profiles.py::export_profile`
(строка 2175) и `import_profile` (2205) делают `.tar.gz`, вырезают `auth.json`,
`.env` и `bot-desktop`, вычищают секреты из текста, и импорт идёт через
`safe_extract_targz`. CLI: `hermes profile export|import`. HTTP:
`POST /api/profiles/{name}/export` и `POST /api/profiles/import`.

**Скилы как переносимый архив — не существует.** `hermes skills snapshot
export` пишет JSON-манифест `{name, source, identifier}` и при импорте
перекачивает скил по идентификатору. Байтов он не несёт. Установка принимает
только удалённые реестры (`tools/skills_hub_search.py::create_source_router`) —
локального пути и архива нет.

**Готовность инструментов считается, но только для пайплайнов.**
`hermes_cli/pipeline_readiness.py::assess_readiness` (205) даёт
`{readiness_status, readiness_detail}` и различает «не зарегистрирован» и
«зарегистрирован, но `check_fn` вернул false». Потребитель один —
`web_routers/pipelines.py:426`. Скилы и профили её не вызывают.

**`scan_skill` — это безопасность, а не готовность.** `tools/skills_guard.py`
даёт вердикт `safe|caution|dangerous` и проверяет структуру. Зависимости,
объявленные скилом (скрипты, бинарники, переменные, другие скилы), он не
разрешает. Ближайшее к «проанализировать плагин» — `hermes plugins validate`.

**Профиля-как-объекта на UI нет.** `/profiles` рисует карточки и редактирует
всё инлайн (`pages/ProfilesPage.tsx`, 1426 строки). Маршрута `/profiles/{name}`
не существует. `/skills` — монолит на 1659 строк с тремя режимами.
`ProfileBuilderPage.tsx` (834) — только создание: ни правки существующего, ни
шага инструментов. `ToolsetConfigDrawer` — модалка, а не панель.

**Чат с произвольным профилем открывается ссылкой** `/chat?profile=<name>` —
`ProfileProvider` принимает параметр при рендере. Модель выбирается
глобально на уровне профиля (`POST /api/model/set`) и применяется только к
свежему PTY: `ModelReloadConfirm` перезагружает страницу. Параметра `?model=`
нет.

## Чего нет и что будет стоить

| Возможность | Статус | Цена |
|---|---|---|
| Импорт профиля из архива, загруженного из браузера | точка приёма нет — только путь на диске | малая: `stream_upload_to_path` уже есть в `web_routers/ops.py:646` |
| Скил как `.tar.gz` | отсутствует | средняя: запись каталога + установка по локальному пути |
| Отчёт о готовности профиля | отсутствует | малая: переиспользовать `assess_readiness` |
| Анализ скила (зависимости, бинарники, env) | отсутствует | средняя: новый обход манифеста |
| `/profiles/{name}` как страница | отсутствует | средняя: экран + роут |
| `?model=` для чата | отсутствует | малая: запись модели перед переходом |

## Экран

Одна страница `/profiles/{name}` вместо разбросанных настроек.

**Слева — список профилей.** Не `<select>`, как в `ProfileSwitcher`, а панель с
поиском и у каждого профиля сводка: модель, число скилов, число инструментов,
состояние гейтвея. Переключение профиля перестраивает правую часть, как
`ProfileKeyedRoutes` уже делает сегодня.

**По центру — вкладки состава:**

- **Идентичность** — описание, SOUL, алиас.
- **Модель** — выбор модели и провайдера, переиспользуя `GET /api/model/options`.
- **Скилы** — свои, из хаба, выключенные; создание, редактирование, удаление.
  Отдельный блок **«Приобретённые скилы»**: что профиль заработал сам, чем он
  отличается от базового набора. Сейчас этого различия в интерфейсе нет вообще.
- **Инструменты** — тулсеты сеткой с переключателем и панелью настройки
  провайдера вместо нынешней модалки.
- **MCP** — подключения, редактирование через уже существующий билдер.
- **Архив** — экспорт в файл, импорт загрузкой, состав архива до импорта.

**Справа — предпросмотр и вердикт.** Что агент реально получит: итоговый
системный промпт, активные тулсеты, подключённые MCP. Сюда же кнопка
**«Анализировать»** и результат.

## Кнопка «Анализировать»

Одна кнопка, три уровня отчёта — пользователю показывается сводка, детали
раскрываются.

1. **Структура.** Каталоги на месте, `config.yaml` и `.env` читаются, нет
   конфликтующих идентификаторов. Близко к существующему `_check_profiles`.
2. **Готовность.** Каждый тулсет и каждый инструмент, который скил или MCP
   называет: зарегистрирован ли и проходит ли `check_fn`. Прямое переиспользование
   `pipeline_readiness.py` — там уже различаются «нет» и «есть, но выключен».
3. **Скилы.** Для каждого: валиден ли frontmatter, какие файлы referenced
   существуют, какие скрипты и бинарники объявлены и есть ли они. Частично
   переиспользует `tools/skill_linter.py::lint_skill`, который сейчас вызывается
   ровно из одного места и не имеет ни CLI, ни HTTP.

Отчёт не «чинит» молча: он показывает, чего не хватает, и ничего не
переназначает на ближайшее доступное.

## Импорт из архива

Экспорт уже есть и работает. Не хватает приёма байтов: `POST /api/profiles/import`
ждёт путь на диске, поэтому браузерный дашборд архив загрузить не может —
только вызвать экспорт по пути. Нужен `multipart` с тем же
`stream_upload_to_path`, что уже применён в `web_routers/ops.py`.

Обязательные шаги: показать состав архива до импорта (что приедет, какие
файлы исключены — секреты вырезаются на экспорте), отказать при конфликте
имён, и после импорта сразу прогнать «Анализировать» на новом профиле.

## Чат с выбранной моделью

Работает уже сегодня в двух шагах: записать модель профиля через
`POST /api/model/set`, затем перейти на `/chat?profile=<name>`. Добавляю
кнопку «Открыть чат» на странице профиля, которая делает ровно это, и выбор
модели — прямо на странице профиля, рядом со вкладкой состава.

Ограничение, которое надо назвать: модель применяется к **свежему** чату, а не
к текущему. Это осознанное поведение (`ModelReloadConfirm`), ломать не буду.

## Порядок работ

1. **Анализировать** — отчёт о готовности. Самое полезное и самое дешёвое:
   переиспользует существующий код и сразу объясняет, почему профиль не работает.
2. **Страница `/profiles/{name}`** — вкладки состава, переиспользуя
   существующие компоненты без переписывания.
3. **Импорт загрузкой** — приём байтов для уже существующего импорта.
4. **Приобретённые скилы** — различение своих и базовых, с источником.
5. **Скил как архив** — отдельная история, это уже дистрибуция.
6. **Панель инструментов вместо модалки** — косметика, в последнюю очередь.

## Побочная находка

В пяти файлах, которые эта работа расширяет, живёт около 57 классов в стиле
Tailwind — мёртвая разметка. Tailwind из проекта убран, Bootstrap 5 на месте,
определён только `.min-h-0` из этого списка. Новая работа идёт на Bootstrap,
но эти классы стоит вычистить в том же проходе: они читаются как работающие.
